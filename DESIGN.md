# Fleet Social design context

Fleet Social is a private operator workspace for reviewing and accounting for Fleet project posts. The approved Nocturne direction keeps the existing calendar-first, narrow editorial hierarchy and floating navigation, now on warm dark surfaces. It is a visual-system change, not a new publishing workflow.

The base canvas is near-black #12110f, with quiet surface #1c1b18, raised card #24221e, cream text #f6f1e6, muted text #b8b0a2, and line #393630. Gold #d3a75d identifies the primary action, active navigation, and focus ring. Keep the page restrained: one primary action in each decision context, legible body copy, and no decorative color competing with a media review.

Semantic states must stay distinct on dark surfaces: awaiting approval is amber; approved is green; scheduled and delivered have their own cool/green cues; failed is red; an uncertain provider outcome is violet and must not look like an ordinary retryable failure. Text labels accompany every color. Status palettes apply to banners, calendar events, post cards, and account/draft states, including loading, empty and error surfaces.

Project ownership and approval appear in the composer where the owner decides what to send. Per-account receipts and uncertain outcome reconciliation appear in Posts where the owner checks delivery. An uncertain result offers explicit owner reconciliation before a retry, because blindly retrying may duplicate a publication. Published links open the exact destination when known.

The login, calendar, review, create, posts, settings, accounts, connections, and drafts all use these same surfaces and typography. Keep keyboard labels, visible gold focus, touch-sized controls, and responsive single-column behavior. Media stays faithfully previewed rather than recolored or filtered. Reuse the existing project components; no new UI library or runtime dependency is needed.
